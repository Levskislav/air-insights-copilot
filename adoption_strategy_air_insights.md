# Стратегия за adoption: Air & Insights Copilot (разширен с сняг + маршрути + места)

Това е практическа стратегия как да постигнеш **реално използване и растеж** (adoption) след като надградиш агента с:
- **снеговалеж** и **снежна покривка/снегова дълбочина**
- **въвеждане на населено място по име** (не координати) чрез geocoding
- **времето по целия маршрут** при пътуване с кола от точка A до точка B

---

## 1) Какво продаваш (позициониране) — “едно изречение”
Не “още една прогноза”, а:

**„Копилот за решения: безопасно ли е да тичам/пътувам/карам към планината, като взема предвид въздух + сняг + времето по маршрута.“**

Това е важно за adoption, защото:
- хората не купуват “данни”, купуват **решение на тревога/риск**
- конкурираш се не с “API”, а с навика “пускам няколко приложения и гадая”

---

## 2) Кои са първите ти потребители (сегменти) и защо
### A) Зимни пътувания и планина (най-силният “аха” момент)
**Кои:** хора, които пътуват до Боровец/Банско/Витоша, ски, сноуборд, туризъм.  
**Болка:** “Ще има ли снеговалеж по пътя? Колко сняг е горе? Ще е опасно ли?”

Тук снегът + маршрутът дават най-ясна стойност.

### B) Шофьори с чести маршрути
**Кои:** комютъри, куриери, доставчици, B2B логистика.  
**Болка:** “Има ли лошо време по маршрута ми между 06:00–09:00?”

### C) Хора, чувствителни към въздуха / спортуващи
**Кои:** бегачи, родители, астма/алергии.  
**Болка:** “ОК ли е да съм навън тази вечер?”

---

## 3) Продуктовите “aha moments” (какво трябва да усети човек на 1-ва сесия)
Adoption се случва, когато в първите 60–90 секунди потребителят получи **ясно решение**.

### Aha #1: „Тръгвам от София до Боровец в 7:00 — какво ще е по пътя?“
Изходът трябва да има:
- кратък verdict: **OK / caution / avoid**
- **най-рисковите 1–2 сегмента** (пример: “Самоков–Боровец 08:10–08:40: снеговалеж, ниски температури”)
- 1–2 конкретни действия: “измести тръгването”, “вземи вериги”, “карай по-ниска скорост” (без да се правиш на пътна полиция)

### Aha #2: „Колко сняг има в Банско и ще вали ли утре?“
- 1 изречение “снежна покривка/снегова дълбочина” + тенденция
- кратка прогноза за снеговалеж
> Open-Meteo Forecast API поддържа hourly променливи **Snowfall** и **Snow Depth** (снеговалеж и снежна дълбочина). citeturn0search0

### Aha #3: „ОК ли е да тичам тази вечер?“
- verdict + обосновка с PM2.5/PM10 + температура
> Open-Meteo Air Quality API приема координати и връща hourly прогноза, включително за **pm2_5** и **pm10**. citeturn0search1

## 4) UX стратегия за adoption (как да изглежда продуктът)
### 4.1 Премахни координатите от UX (вход по “име”)
Потребителят не мисли в lat/lon.

**Какво да покажеш:**
- поле “Град/място”
- autocomplete предложения
- “Запази като любимо”

**Защо:** намалява friction → повече activation.

**Технически избор:** Google Geocoding API (или Places Autocomplete)  
- Geocoding API конвертира адрес/място в координати. citeturn0search2  
- За да го ползваш трябва Google Cloud project с **billing enabled** и включен Geocoding API. citeturn0search5  
**Adoption импликация:** ако продуктът е безплатен, Google може да вдигне себестойността → трябва лимити/кеш/или fallback.

**Практика за adoption + cost control:**
- кеширай резултати от geocoding (например 7 дни)
- нормализирай заявки (“София, България”)
- лимитирай autocomplete заявки (debounce)

### 4.2 “Quick actions” вместо празен чат
На първи екран дай бутони:
- “Air + Run safety (next 6h)”
- “Snow conditions (today/tomorrow)”
- “Route weather (A → B)”

**Защо:** начинаещ потребител не знае какво да пита → quick actions увеличават activation.

### 4.3 “Explainability”, но кратко
За доверие:
- покажи ключовите числа (avg PM2.5/PM10, temp, snowfall, snow depth)
- 1–2 изречения “защо мисля така”
- “Confidence: high/medium/low” (ако данните са sparse)

## 5) Стратегия за “Route weather” (как да стане продуктово полезно)
### 5.1 Какво потребителят очаква
Не “100 точки с време”, а:
- “Кога и къде ще е най-зле по маршрута”
- “Какви рискове има (сняг/температура/видимост/вятър)”
- “Какво да направя (час на тръгване/етапи/намаляване на риск)”

### 5.2 Как да го опаковаш като feature
**Route Weather Report**:
- Summary (1 абзац)
- Таблица: 3–6 “checkpoint”-а (напр. на всеки 30–50 км или ключови места)
- “Worst window” секция
- CTA: “Save this route” + “Notify me 2h before departure”

### 5.3 Retention loop
Запазени маршрути → сутрешен digest:
- “Маршрут София→Пловдив: всичко ОК”
- или “Внимание: снеговалеж около Пазарджик 07:00–09:00”

## 6) Growth стратегия по канал (Track B + Track A)
### 6.1 Track B (отворен/безплатен): Web/PWA + shareable reports
**Цел:** бързо достигане до реални хора, минимален friction.

**Тактики:**
- PWA (Add to Home Screen) → изглежда “като приложение”
- “Share link” за Route report (хората си пращат по Viber/WhatsApp)
- SEO страници за “София Банско време по маршрут”, “снеговалеж Витоша” (локалните търсения са силни)

### 6.2 Track A (Microsoft): Copilot Studio за B2B adoption
**Цел:** adoption в организации (логистика/field service), където Teams е ежедневен.

**Тактики:**
- “Travel & Safety Copilot” за Teams
- шаблонни въпроси (cards) + pinned app
- пилот с 1–2 компании: доставка/логистика

## 8) Метрики за adoption (как да знаеш, че работи)
### North Star Metric (предложение)
**“Weekly decisions helped”** = брой уникални седмични сесии, в които потребителят получава verdict (OK/caution/avoid) за:
- run
- snow conditions
- route

### Funnel метрики
**Acquisition**
- visits → first query rate
- share clicks (ако имаш shareable reports)

**Activation**
- % потребители с първи успешен отговор (<30 сек)
- % които използват “place name” (не координати)
- % които правят “route weather report”

**Retention**
- D1, D7, D30 retention
- # saved places/routes per user
- alert opt-in rate

**Quality / Trust**
- p95 latency (особено при кеш)
- cache hit rate
- upstream error rate (Open-Meteo / geocoding / directions)
- LLM fallback rate

## 9) План за rollout (0–90 дни)
### Фаза 1 (0–2 седмици): “Snow + Place name”
- добави snowfall + snow depth в /analyze (или отделен endpoint /snow)
- добави geocoding (име → координати)
- UX: quick actions + любими места

**Цел:** по-лесно влизане + силен зимен use case.

### Фаза 2 (2–6 седмици): “Route weather report”
- directions (A→B) + sampling + ETA
- route report UI + share link
- кеш на route резултати (10–30 мин)

**Цел:** силен differentiator → споделяне/вирусност.

### Фаза 3 (6–12 седмици): “Retention engine”
- saved routes + alerts
- morning briefing
- basic personalization (“по принцип тичам вечер”)

## 10) Рискове за adoption и как да ги управляваш
### Риск: “не ви вярвам”
Мерки:
- покажи числата + източника
- ясно “confidence” и “uncertainty”
- disclaimer: “не е официален бюлетин”

### Риск: разходи за Google Maps APIs
- Geocoding изисква billing. citeturn0search5turn0search2  
Мерки:
- кеширане + rate limiting
- лимит на безплатните заявки
- (по избор) open-source fallback за геокодиране/маршрути

### Риск: “твърде сложно”
Мерки:
- quick actions
- default сценарии (“София → Банско”)
- “Try it” пример
